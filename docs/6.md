# AIを使ったコーディングがこんなに疲れさせるワケ

AIを活用したコーディングは、一見すると開発の効率化をもたらすはずだった。しかし実際に使ってみると、従来のコーディングとは異なる種類の疲労が発生する。この疲労の正体は何なのか。

## プロンプト相談室の無限ループ

AIにコードを書かせるという作業は、実質的には延々とAIとの対話に変わってしまう。開発者は自分の要件を説明し、AIが提案したコードを確認し、修正を依頼する。このサイクルが何度も繰り返される。

従来のコーディングであれば、開発者が一人で黙々と書き進めることができた。しかしAI相手では、毎回丁寧に意図を伝える必要がある。それでもAIは文脈を完全には理解できず、同じ説明を何度も繰り返させられる。要件を言い直す回数が増えるほど、心理的な負荷も増していく。

## 「これ本当に正しいのか」症候群

AIが生成したコードを見たとき、開発者は不安に襲われる。動作するのか、バグはないのか、セキュリティは大丈夫なのか。

自分で書いたコードなら、ロジックを追える。しかしAI生成のコードは検証項目が増える。正当性の確認、パフォーマンスの検討、エッジケースへの対応。読む行数が書く行数を大幅に上回ることになる。生成されたコードの意図を理解するまでに、かなりの時間と集中力を消費する。

## プロンプト設計という新たなスキル習得

AIを効果的に使うには、従来のプログラミング知識に加えて、新しいスキルが必要になった。どのレベルの詳細さで指示を出すべきか、どのタイミングでAIを使うべきか、提案されたコードをどう評価するべきか。

これらの判断は経験を通じてしか学べない。試行錯誤の過程で認知負荷が蓄積される。最適なプロンプト作成方法を探り続けることは、実装そのものと同じくらい疲労が大きい。

## 決定疲労の増加

AIは複数の実装案を提示することが多い。開発者はその中から最良のものを選ばなければならない。「このアプローチを採用すべきか、別の案を試すべきか、自分で書き直すべきか」という判断が増える度に、疲労は累積していく。

選択肢が多いことは自由度が高いように見えるが、実際には判断コストが増大している。

## 創造性と達成感の喪失

AIが多くの実装を引き受けると、開発者自身が問題を解く満足感が減少する。コード生成の指揮者に成り下がったような感覚は、プログラマーとしての充実感を低下させる。

自分の手を動かして実装することの喜びが奪われ、代わりにAIとのやり取りと検証作業だけが残される。この心理的な変化も、疲労の一因となっている。

## 結論

AIコーディングの疲労は、技術的な問題というより心理的なものである。ツールとしてのAIを最大限活用するには、AIを完全な解決策ではなく補助手段として位置づけ直す必要がある。適切な場面での使用と、開発者自身の思考時間のバランスを保つことが、持続可能なコーディング環境を作る鍵となるだろう。
